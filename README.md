# GenKit — AI Tools SaaS

AI-powered generation tools built on [OpenSaaS](https://opensaas.sh) + [Wasp](https://wasp.sh).

---

## What is GenKit?

GenKit gives users 7 AI tools with a **free tier that costs the developer $0** — powered by Groq's free API and Pollinations.ai. Pro users get GPT-4o and DALL-E 3 quality.

## Tools

| Tool | Free Tier | Pro Tier |

| Product Description | Groq Llama 3.3 (unlimited, free) | GPT-4o + bulk |

## Setup & Run

### Step 1 — Install Wasp

```bash
curl -sSL https://get.wasp.sh/installer.sh | sh
```

Restart your terminal after install. Verify:

```bash
wasp version
```

### Step 2 — Clone / navigate to project

```bash
cd /var/www/minhazul.site/ai-tools-app
```

### Step 3 — Configure environment variables

Copy the example file and fill in your keys:

```bash
cp .env.server.example .env.server
```

Open `.env.server` and set at minimum:

```env
# Required for all text tools (free tier)
GROQ_API_KEY=gsk_your_groq_key_here

# Required for pro tier
OPENAI_API_KEY=sk-your_openai_key_here

# Required for payments (use Stripe for simplest setup)
STRIPE_API_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...
PAYMENTS_PRO_SUBSCRIPTION_PLAN_ID=price_...

# Required: your admin email
ADMIN_EMAILS=your@email.com
```

### Step 4 — Start the database

**Option A: Use Wasp's built-in DB** (easiest — no Postgres install needed):

```bash
# Terminal 1
wasp start db
```

Wait for "DB ready" message before continuing.

**Option B: Use your own Postgres**:

```env
# Add to .env.server
DATABASE_URL=postgresql://user:password@localhost:5432/genkit
```

### Step 5 — Run database migrations

```bash
# Terminal 2
wasp db migrate-dev
```

When prompted for migration name, type something like: `init`

### Step 6 — Start the app

```bash
# Terminal 2 (same terminal after migrations)
wasp start
```

App runs at:
- **Frontend**: http://localhost:3000
- **Backend API**: http://localhost:3001

## Database Models

### GenerationJob (new)

```prisma
model GenerationJob {
  id        String   @id @default(uuid())
  createdAt DateTime @default(now())
  user      User     @relation(fields: [userId], references: [id])
  userId    String
  toolType  String   # image | product_desc | seo_meta | social_caption | code_explainer | summarizer | blog
  prompt    String
  result    String   # text result or image URL
  isPro     Boolean  # was pro API (OpenAI) used?
}
```

### User (from OpenSaaS — relevant fields)

```prisma
subscriptionStatus  String?   # 'active' = Pro user
subscriptionPlan    String?   # 'hobby' | 'pro'
credits             Int       # unused by GenKit tools (all unlimited)
```

## Free vs Pro — How It Works

Every server action checks subscription status:

```typescript
const isPro = user.subscriptionStatus === SubscriptionStatus.Active;

if (isPro) {
  // OpenAI GPT-4o or DALL-E 3
} else {
  // Groq Llama 3.3 or Pollinations.ai
}
```

**Blog Writer** is pro-only — throws HTTP 403 for free users.

## Deployment

### Build for production

```bash
wasp build
```

Output goes to `.wasp/build/`. Contains:
- `web-app/` — static React app (deploy to Vercel / Netlify / S3)
- `server/` — Node.js server (deploy to Railway / Render / VPS)

### Environment variables for production

Set all `.env.server` variables in your hosting platform's environment settings. Key changes for production:

```env
# Change Stripe to live keys (not test)
STRIPE_API_KEY=sk_live_...

# Set your real domain
# (configured in wasp build output)
```

### Stripe webhook for production

Point Stripe webhook to: `https://your-domain.com/payments-webhook`

## Common Issues

**`GROQ_API_KEY is required` on startup**
→ Add `GROQ_API_KEY=gsk_...` to `.env.server`

**`Cannot find module 'groq-sdk'`**
→ Run `npm install` inside the `.wasp/out/server` directory after `wasp build`, or Wasp handles it automatically on `wasp start`

**Image not loading (Pollinations)**
→ Pollinations generates on first request — can take 5–15 seconds. Retry if timeout.

**`relation "GenerationJob" does not exist`**
→ Run `wasp db migrate-dev` to apply schema migrations

**Port 3000 already in use**
→ Kill the process: `lsof -ti:3000 | xargs kill -9`
